# 翻译性能与本地版面缓存

适用于托管的 `pdf2zh_next` 环境，已验证 `pdf2zh-next 2.9.0 / BabelDOC 0.6.2`。更新服务端后，环境检查会安装补丁。此项修改不需要重新安装插件 XPI，也不修改 API、模型或翻译质量设置。

## 默认优化

为版面模型的单页预测增加本地磁盘缓存。重复翻译同一篇论文时，页面图像、模型权重、前后处理代码、ONNX Runtime 版本和推理线程配置全部匹配才复用检测框。换翻译服务、目标语言或重新翻译正文时，仍可复用相同输入的版面预测；正文翻译及后续分段、样式处理继续正常执行。

缓存只包含检测框坐标、类别编号和置信度，不包含正文、页面图片、PDF 文件、密钥或 API 配置。缓存键为内容摘要。缓存使用 JSON，原子写入；缓存损坏、无权限或不匹配时重新推理，不把缓存故障当作翻译失败。

默认目录为用户目录下的 `.cache/zotero-pdf2zh/layout-v1`，按文件数、体积及保存时间清理，目标上限为 2048 个页面、64 MiB、30 天；清理在写入时定期执行。只清理本缓存的摘要文件，不递归删除目录。

环境变量可调整缓存：

- `ZOTERO_PDF2ZH_LAYOUT_CACHE=0`：关闭缓存。
- `ZOTERO_PDF2ZH_LAYOUT_CACHE_DIR`：指定缓存目录。

## 首次翻译与线程设置

本地 PDF 解析、版面识别、分段与排版不受 API QPS 控制。提高 QPS 不会加快这些步骤。首次翻译仍需识别页面；版面缓存主要加速重复翻译。

实测发现，将 ONNX CPU 线程数直接减到 2 或 4 可能使单页推理变慢；内存不足与磁盘换页也会导致整篇耗时明显波动。因此默认保持原引擎的 CPU 线程与忙等策略，不预设固定线程数，不切换模型、不降低分辨率或检测阈值。

需要自行对照测试时，可在启动服务前设置下列环境变量；不设置即保持引擎默认：

- `ZOTERO_PDF2ZH_CPU_THREADS=4`：示例值，支持 0（引擎自动）或 1～8，且不超过逻辑 CPU 数。
- `ZOTERO_PDF2ZH_DISABLE_SPINNING=1`：关闭 ONNX 空闲线程忙等，可能减少后台 CPU 消耗，速度影响需实测。

这些设置只作用于纯 CPU 推理；现有加速器配置保持原样。

对于内存紧张的电脑，先关闭不用的软件和浏览器标签，避免同时运行多个翻译引擎。可选择文字的 PDF 可对照测试关闭 OCR 兼容模式；扫描件仍需对应处理。上述操作的收益取决于文档与机器状态。

## 验证

```sh
python -m unittest discover -s tests -p test_layout_performance.py -v
python -m unittest discover -s tests -p test_pdf_layout_repair.py -v
```

回归覆盖精确命中、页面变化、模型升级、运行参数变化、损坏缓存、无写入权限、空检测、失败不缓存、原坐标与置信度保留、限额清理及安装幂等。测试无需翻译 API。

一次 14 页文档的冷缓存/热缓存对照中，版面阶段从 14.35 秒缩短到 3.39 秒，正文翻译前的处理总耗时从 30.87 秒缩短到 19.84 秒；14 页全部命中，检测框和分段结果摘要完全一致。缓存约 22 KB。此对照不包含翻译 API 请求与最终排版，也不能推算所有机器的整篇耗时；内存压力和换页会显著影响测量。
